Daily price alert scan - 12 October 2026

The existing bearer-protected daily cron now enqueues a Vercel Workflow and returns HTTP202 with runId. It no longer stops after the first80 rows. Workflow5.2.0 is integrated via withWorkflow(nextConfig); no extra paid service is provisioned.

Each durable step runs one bounded batch with the existing48-second budget, notification claims and cancellation fences. Selection includes active, un-cancelled, unexpired rows with an enabled per-alert delivery channel, present at the captured snapshot and not checked since UTC midnight. New rows created before the daily run are included. Completed rows are excluded on replay. Remaining eligible count is verified in storage after each batch; failed persistence retries instead of falsely completing. Steps retry up to8 times. Outages beyond that remain a failed run in Workflow observability and will be eligible for the next daily scan.

Same-day active duplicates coordinate by deterministic hook before processing. After100 batches, a durable child continuation bounds replay history while retaining the same snapshot. Daily cron schedule remains unchanged, compatible with Hobby cron frequency. Rows created after the snapshot await the next daily scan.

Production requirements: System Environment Variables enabled (VERCEL_DEPLOYMENT_ID) and Fluid compute. Root confirmed both already enabled on the main project. The exact proxy matcher does not intercept .well-known/workflow. Generated handlers are ignored in Git and rebuilt on deployment. Verify Vercel-generated queue trigger/flow and webhook handlers during deployment. Do not smoke-test the real price cron: it sends actual notifications.
